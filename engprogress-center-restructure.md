# EngProgress — Center Console Restructure

Scope: organization (education center) side only. Finance/Invoices/Salary excluded — logic below is written so they slot in unchanged later.

Guiding constraint: this is **an operating console, not a CRM**. Every surface must answer one of four questions:

1. Who exists here? (teachers, groups, students, timetable)
2. What has to happen today? (registers, practice, marking)
3. How are the students actually doing? (bands, weaknesses, progress)
4. Money.

If a screen doesn't answer one of those, it shouldn't be a screen.

---

## 1. Vocabulary — fix this first

The UI currently uses three words for the same thing. Nav says **Groups**, breadcrumb says **CLASSES**, settings panel says **class**, timetable says **lesson**.

Settle on:

| Term | Means | Never means |
|---|---|---|
| **Group** | The cohort. Has a teacher, a roster, a schedule, a fee. | A single meeting |
| **Lesson** | One timetabled occurrence of a group | The cohort |
| **Practice** | A task set by a teacher or generated by a student | A lesson |
| **Attempt** | One student's submission of one practice | The practice itself |
| **Report** | The marked output of one attempt | An aggregate dashboard |

Delete the word "class" from the product entirely.

## 3. Global rules

These apply to every page and remove most of the current inconsistency.

**R1 — One date range, and it governs everything.**
The `Last 90 days` picker at top right must control every number on the page. Any figure that is deliberately fixed-window (gone quiet, last active, today's register) is **always relative to now** and must never respond to the picker. Label those explicitly: "gone quiet — 14 days, always current".

**R2 — Never average across skills.**
Writing, Reading, Listening, Speaking each stand alone. Any place currently showing a single "band" for a group, center, or teacher must show either:
- per-skill bands with sample size — `Writing 5.5 · 12 essays · 8 students`, or
- one named skill as the headline (Writing, since it is graded most), clearly labelled.

Remove: `Average band across the center`, `Avg band` on group cards, `AVG BAND` on the teachers table.

**R3 — Sample size is always visible.**
Never show a band without the count behind it. `1.0` from one essay is noise presented as fact. Below 3 attempts, show the number greyed with `provisional`.

**R4 — Every empty state has one action.**
"Nothing graded yet." → `Nothing graded yet — set the first practice →`. "not measured" → `not measured — assign a placement →`.

**R5 — Nothing is deleted, things are archived.**
Students, groups, and teachers get `left` / `closed` / `inactive` states. History, attendance, and invoices stay intact.

## 4. Today (replaces Overview)

You said you weren't happy with the dashboard. The current problem is that it mixes four kinds of information — roster counts, alerts, today's schedule, and analytics — at equal weight, and two of the KPIs are self-contradictory (`Active students 3 / 1 active`, `Groups running 3 / 2 idle`).

A center admin opens this once a morning. It should answer: *what is broken, and what happens today.*

### Layout

**Row 1 — four counters, unambiguous labels**

| Counter | Definition |
|---|---|
| Students enrolled | active students; sub-line: `n without a group` |
| Practised this week | `1 of 3` — distinct students with ≥1 attempt since Monday |
| Gone quiet | students with no attempt in 14 days, enrolled, not paused |
| Registers to mark | lessons that have finished today and aren't saved |

Remove `Groups running / idle` and `Teachers / running a class` — those belong on their own pages. Remove `Graded practices` — it belongs in Results.

**Row 2, left — Needs attention**

Keep this. It's the strongest thing on the current dashboard. Tighten it:
- Max 6 rows, one row per alert *type* with a count, never one row per instance.
- Sorted by severity, then age.
- Every row resolves to a specific destination, not a list page.
- Dismissible for 7 days by the center admin, with the dismissal logged.

**Row 2, right — Today**

Today's lessons in time order: group · teacher · room · time · register state (`open` / `marked` / `cancelled`) with a one-click **Mark**. This must use exactly the same query as the Attendance page — the current mismatch (Overview says 3 open, Attendance says nothing timetabled) is a bug in one of the two.

**Row 3 — two learning panels**

- **Writing band across the center** — trend line over the selected window, per skill via tab, with `n essays` under it.
- **Where the center loses marks** — top 3 weakest criteria across all graded work, with the share of students affected. e.g. `Coherence & Cohesion — lowest criterion for 8 of 11 students`.

That second panel is the reason a center owner logs in. It converts directly into "run a CC workshop Thursday." Right now that insight exists only as a sentence buried on the student page.

### Alert catalogue

Define these explicitly rather than leaving them to whatever the query returns.

| Alert | Trigger | Severity | Destination |
|---|---|---|---|
| Student gone quiet | enrolled, active, no attempt in 14d | high | Students filtered |
| Unmarked submissions | attempt submitted >48h ago, no final band | high | Marking queue |
| Register not marked | lesson ended >2h ago, unsaved | high | Attendance for that lesson |
| Group with no practice | 0 practice set in 14d, group active | medium | Group → Practice |
| Low completion | completion <50% over window, ≥3 practices set | medium | Group → Practice |
| Two absences in a row | same student, consecutive lessons | medium | Student |
| Student far below target | latest band ≤ target − 1.0, ≥2 attempts | low | Student |
| Teacher with no group | active teacher, 0 groups | low | Teachers |
| Group with no teacher | group active, teacher null | high | Group settings |

## 5. Groups

The group detail page is already the best-structured screen you have — the `Students / Practice / Attendance / Money` tab set is right. Keep it. Changes:

**Group list**
- Remove `Avg band` from the card (R2). Replace with `Writing 5.5 · 12 essays` or `not measured yet`.
- The `Active / No practice` badge is good. Add `No teacher` and `Closed`.
- Add a `Closed` filter alongside All / Active / No teacher.

**Group → Students tab**
- Currently shows `Report | Password | Remove` per row. Rename `Remove` → `Move or remove`, opening a small sheet with: move to another group / mark as left / remove from center. Straight deletion of a student who owes money is a support ticket waiting to happen.
- Add a `Target` column that's editable inline — target band already exists in the data but is only visible here.

**Group → Practice tab**
This tab carries the most weight and is the least defined. It should show, per practice:
`date set · skill · task type · set by · handed in n/m · marked n/m · median band`
plus a row action `Remind the ones who haven't`.

**Group settings panel**
- `When it meets` — good model, keep "one row per day, edited together".
- Add **conflict checking on save**: same teacher two places at once, same room two places at once. Warn and block.
- Add **cancel a lesson** (date + reason). Cancelled lessons are excluded from attendance %, from the fee divisor, and from "register not marked" alerts. Without this, both attendance and part-month billing are wrong the first time a teacher is ill.
- Telegram channel: keep. Show *which* channel by name, not just "Connected — Test".

## 6. Students

Purpose: search and individual intervention across groups. The group page handles teaching; this page handles the one student someone is asking about.

Changes:
- Add **status**: `active` / `paused` / `left`. Paused students are excluded from gone-quiet alerts, attendance denominators, and invoices. This is currently missing and it distorts every metric on the dashboard.
- Add bulk selection → message / move group / export.
- The four filter cards are good. Replace `In no group 0` with `Paused or left` once status exists.
- Enrolment sheet is well designed. Two additions: **Target band** at enrolment, and **Assign placement practice** (checkbox, default on).

### Placement — worth adding

A student's first graded attempt is currently also their baseline, which means you can never show progress, only a current position. Education centers sell progress.

Fix, low complexity: at enrolment, optionally assign a practice tagged `placement`. Its band becomes the student's baseline. Every band display then reads `Writing 5.5 · +1.0 since placement`. This turns the student page and the parent report from a snapshot into a story, and costs one boolean plus a tag.

### Student detail page

This page is already good — `Band by skill`, `Homework`, `Their own practice`, `At a glance`, and the two weakness panels. Keep the structure. Add:

- **Baseline vs now** on each skill bar.
- Split `Their own practice` clearly from set homework — you already do, and the distinction is genuinely valuable. Surface it in Results too: self-directed practice volume is the strongest predictor of improvement you'll have.
- Every homework row's `Full report →` opens the attempt report (section 8).
- **Export report (PDF)** button — parent-facing.

## 7. Teachers

- Remove the `AVG BAND` column (R2, and it implies teacher quality from a one-essay sample).
- Replace with: `Groups` · `Students` · `Practices set (window)` · `Marking turnaround` · `Attendance marked %` · `Status`.

- Teacher detail page doesn't exist yet — add a light one: their groups, their timetable, their unmarked queue, their salary rule.

## 8. Results (replaces Reports)

This is the part you're least happy with, and correctly — the current page shows *Handed in* and *Nothing back yet*, which is engagement data, not learning data. Engagement belongs on Today and in Practice. Results should be about bands and weaknesses.

Four levels, each drilling into the next.

### Level 1 — Center

Filters: date range, group, teacher, skill.

- **Band distribution** per skill — histogram, not an average. `n students, n attempts`.
- **Movement** — how many improved / held / declined vs their previous attempt in the window.
- **Top weaknesses** — the ranked list, per skill:
  - Writing: by criterion (Task Response, Coherence & Cohesion, Lexical Resource, Grammatical Range & Accuracy)
  - Reading & Listening: by question type
  - Speaking: by criterion (Fluency, Lexis, Grammar, Pronunciation)
  Each row: `criterion · lowest for n of m students · avg band on it`.
- **Export CSV** — keep.

### Level 2 — Group

Same, scoped to one group, plus:
- Roster table sorted by weakest skill.
- **What to teach next** — the criterion the largest share of this group is lowest on. One sentence, prominent.

### Level 3 — Student

Your existing student page. Reached from either level above.

### Level 4 — Attempt report

This is the surface you described and it currently has no defined design. It's the product's core artefact — everything else is scaffolding around it.

**Header:** student · group · practice · skill · task type · submitted · marked by

**Body, per skill:**

*Writing*
- Band per criterion, four bars.
- One examiner-style comment per criterion, 2–3 sentences, referencing their actual text.
- Inline annotations on the essay: highlighted spans tagged `grammar` / `cohesion` / `lexis` / `task` with a hover note and a suggested rewrite.
- `What to fix next` — exactly 3 concrete actions, ordered by band impact.

*Reading / Listening*
- Question-by-question: their answer, correct answer, question type.
- Missed-by-type roll-up (this is what feeds "most-missed types" upward).

*Speaking*
- Per-criterion band + comment, timestamps into the audio for the moments cited.

**Footer — the important bit:**
- `AI band` and `Final band` stored as separate fields.
- Teacher can override any criterion, must leave a one-line reason.
- Report stamps: `Marked by AI · reviewed by Madina Zaynidinova · 13 Aug`.

Why this matters commercially: an education center will not put its name on grades it can't correct. The override plus provenance stamp is what makes a center comfortable selling this to parents, and it costs you two columns and a modal. It also gives you human-corrected labels, which is the most valuable dataset you could accumulate.

**Marking queue** — a derived view: all attempts where `final band is null`, grouped by teacher, sorted oldest first. Teachers see their own; center admin sees all. This is what makes the "unmarked submissions" alert actionable.

## 9. Practice (new)

Light page. Answers: what has been set across the center, and is it landing.

Table: `practice · group · teacher · skill · set on · handed in n/m · marked n/m · median band`
Filters: group, teacher, skill, date, status (`set` / `overdue` / `complete`).
Row actions: open group, remind non-submitters.

Also holds the **practice library** — reusable tasks the center has generated, so teachers stop regenerating the same Task 2 prompt. Tag by skill, task type, level. Teacher can save any generated practice to the library.

## 10. Attendance & Timetable

### Attendance
- Keep the "everyone starts present" default — it's correct and fast.
- Add **`excused`** as a fourth state. Absence alerts must ignore excused absences, otherwise the alert becomes noise within a week.
- **Lock registers after 7 days**; center admin can unlock, and the unlock is logged.
- Attendance % excludes cancelled lessons from the denominator.
- Absence alert: 2 consecutive absences → alert + optional automatic Telegram message.
- The top-level Attendance page should be purely operational (mark today, jump to a date). All attendance *analysis* lives on the group page and in Results.

### Timetable
- Hide the branch selector when the center has one branch. Multi-branch is a real feature but it shouldn't cost single-branch centers a control they'll never use.
- Room column headers currently render as bare `12` and `32`. Label them `Room 12 · 43 seats`.
- Recurrence model ("one row per day, edited together") is right — keep it, don't build full RRULE.
- Add **center holidays** in Settings. Holiday dates generate no lessons, no registers, no fee divisor entries.
- Conflict detection on save (teacher, room).

## 12. Announcements

You flagged this one too. Current issues: it sits under INSIGHT, the audience picker is single-select, there's no scheduling, and `not opened yet · 5 sent` is a discouraging headline metric that doesn't tell anyone anything.

The deeper point: **manual announcements are rare; automatic messages are what actually change behaviour.** The structure should reflect that.

### Two tabs

**Broadcast** (manual)
- Audience: Everyone / Teachers / Students / specific groups (multi-select) / specific people (multi-select). Same control, just allow multiple.
- Subject + message, unchanged.
- **Send now / schedule for later.**
- **Pin to student home until [date]** — for things like mock exam week.
- Channels: in-app bell (always on) + Telegram, listing which channels will receive it by name + email where an address exists.
- Delivery line: `3 of 5 seen · posted to 1 Telegram channel`. Not "not opened yet".

**Automatic** (toggles + editable template, ~6 total)

| Message | Trigger | To |
|---|---|---|
| New practice set | teacher sets practice | group students + Telegram |
| Results ready | final band saved | student |
| Absent today | register saved with absent | student + Telegram |
| Gone quiet nudge | 7 days no attempt | student |
| Two absences | consecutive | teacher + admin |
| Invoice due | (later) | student |

Each is on/off with an editable template and a placeholder set (`{student}`, `{group}`, `{practice}`, `{band}`). That's the whole feature — no automation builder, no conditions.

## 14. Build order

**Phase 1 — correctness.** R1–R5. Remove cross-skill averages. Fix the today-lessons mismatch. Student status. Lesson cancellation + holidays. Excused attendance. Register locking.

**Phase 2 — the core artefact.** Attempt report (level 4), teacher override + provenance, marking queue. This is where the product lives; everything before it is plumbing and everything after it is presentation.

**Phase 3 — the console.** Today rebuild with the alert catalogue. Results levels 1–3. Practice page.

**Phase 4 — retention.** Placement baselines, parent PDF report, automatic messages, practice library.

**Phase 5 — commercial.** Finance, Invoices, Salary against the now-stable lesson/attendance/status model.

Phase 1 before Phase 2 matters: if lessons can't be cancelled and students can't be paused, every number Phase 2 produces will be defended in a meeting and lost.
